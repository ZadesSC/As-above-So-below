# Proposal for integrating thin rock roof support

## Recommendation

Integrate thin rock roof behavior into the fork’s core assembly first. Follow with a one-tile landing margin for ladders and standard stairs after testing the fork’s connector routing. RimWorld-Patches ships both changes in one addon, but the fork’s landing code also serves grand stairs, existing elevators, and vehicle ramps. The addon’s landing tests cover ladders and standard stairs.

This proposal is based on `Mods/AASBThinRoofSupport` in RimWorld-Patches at `0625edc` and the fork’s vehicle-ramp code at `f290898`. The relevant roof, landing, and connector definitions also match `origin/dev` at `428ba3a`. Use `dev` as the integration base so verification includes the merged grand stairs and vehicle ramps.

## 1. Thin rock roofs and removal

- **Project thin rock as a rooftop.** Share a roof predicate between [sky generation](../Source/V2/ABSkyBandGen.cs#L228) and [live roof sync](../Source/V2/ABSkySync.cs#L297). Route vanilla `RoofRockThin` through the same `AB_RoofSurface` branch as constructed roofs, including the existing orbital projection gate. Keep the roof itself natural in RimWorld’s roof grid so native collapse and roof work still apply. Preserve the generator’s summit classification, the existing pre-generated structure override, and the resolver’s handling of thick and other natural roofs. The addon implements this with two IL transpilers. Direct source changes remove the dependency on the shape of those methods’ compiled code.
- **Guard deliberate removal at both entry points.** Use one check from the `WorkGiver_RemoveRoof.HasJobOnCell` postfix and the `JobDriver_RemoveRoof.DoEffect` prefix. Match addon behavior for thin rock and constructed roofs. On banded maps, translate to the next level and check whether the upper tile’s base terrain is `AB_RoofSurface`, including under a floor finish. A pawn, building, or separate roof above delays the work. The completion check catches occupants that arrive after the job starts. Keep the Remove Roof area active so builders can retry after the tile clears. Reuse the fork’s terrain and occupancy logic where it applies and register the hooks through [HarmonyBoot](../Source/Core/HarmonyBoot.cs). Add localized rejection reasons in the fork’s [keyed strings](../Languages/English/Keyed/AsAboveSoBelow.xml).
- **Use the existing terrain update.** [Sky sync](../Source/V2/ABSkySync.cs#L143) already handles both the floor finish and the rooftop underneath. Removing the finish upstairs exposes the rooftop. Removing the roof downstairs opens an unsupported tile, with the usual floor material recovery. A lower edifice that still supports a wall top can leave `AB_WallTop` and its finish in place. Keep the removal guard at the job level so direct roof-grid changes and native collapse can still reach the existing sync path.
- **Preserve existing saves.** Reuse the existing roof and terrain defs. Preserve `AB_MountainTop` because the saved terrain can be either a real ledge or an older thin-rock shelf. Review the [wall-top load repair](../Source/V2/ABSkySync.cs#L449), which currently sends every wall top with a natural roof below to `AB_MountainTop`. For thin rock, use the new rooftop rule for cells that qualify for that repair and pass the existing projection gate. Keep the repair’s current target scope and verify that legacy mountain terrain survives reload. Saves made with the standalone addon should keep their existing rooftop layers when it is disabled.

## 2. Smaller ladder and stair landings

Use a shared landing margin rule for the destination connector in [landing construction](../Source/V2/Building_ABStairs2.cs#L406) and [legacy roof backfill](../Source/V2/ABSkySync.cs#L520). For ladders and standard stairs, use the rotated occupied footprint plus one tile. That gives a 3×3 landing for the 1×1 ladder and a 3×4 or 4×3 landing for the fork’s 1×2 stairs. Apply the same margin to excavation and roof-backed platforms. Preserve the existing footprint-only recovery for links standing over open air so a player can trim the apron and keep it trimmed across reloads.

Retain the current margin for grand stairs, existing elevators, and vehicle ramps. The vehicle backend checks [full-width entry and exit lanes](../Source/VehicleRamps/CrossingPatch.cs#L301), and the fork’s pawn routing searches for a reachable exit when a connector mouth is blocked. Keep the [transit search radius](../Source/V2/ABWormholePather.cs#L97) and the separate [breach reveal](../Source/V2/Building_ABStairs2.cs#L355) independent of excavation size. Existing aprons keep their saved terrain and roofs. A legacy rooftop outside the new ladder or stair margin keeps its terrain without acquiring a roof underneath during backfill.

## Verification before release

Build the [core project](../Source/ModSource.csproj) for RimWorld 1.7. The fork’s [test adapter](../Tests/ThinRoofSupport.cs) runs with Harmony and the fork. Use its `RoofFixture` contract, reference the selected Harmony assembly, and set `mode` to `aasb`. Run `aasb.thin-roof-support` for 600 ticks with the framework’s rendered capture enabled. Set `capture` to `before` for the intact rooftop, `after` for removal, or `landing-ladder` and `landing-stairs` for the connector matrix and the corresponding screenshots. The addon’s separate test report covers the original 1.5.7 target.

| Area | Acceptance checks |
| --- | --- |
| Roof generation and sync | An isolated thin roof produces a walkable and buildable upper rooftop during generation and live sync. Its lower roof stays natural. Constructed roofs, overhead mountain, real summit terrain, and orbital projection retain their existing behavior. Flat maps and cells without an upper band are unaffected. |
| Native roof work | Strip a finish upstairs, then remove a thin roof downstairs with a real job. Check material recovery and that open air is impassable. Cover wall-top fallback and the constructed roof case. Check each blocker, a blocker arriving mid-job, and retry after clearing it. |
| Save and upgrade | Save and reload both an intact finished rooftop and an opened tile. Load a pre-integration fork save with legacy mountain terrain. Load a save written with the standalone addon after disabling it and check that rooftop layers and connectors persist. |
| Landing geometry and travel | Exercise all rotations for ladders and standard stairs on open-air and rocky sites. Verify the first and second rings, native travel in both directions, an occupied exit, and apron trimming across reload. Run the [grand stair](../Tests/GrandStairRouting.cs) and [vehicle ramp](../Tests/VehicleRampIntegration.cs) regressions alongside targeted checks for existing elevator links and drafted vehicle crossings with Vehicle Framework. |

## Packaging

Ship the roof feature in `1.7/Assemblies/AsAboveSoBelow.dll` under the fork’s existing package ID. Preserve the MIT notice from `Mods/AASBThinRoofSupport/LICENSE` and credit for imported code or test fixtures. Mark `zades.aasb.thinroofsupport` incompatible with the integrated fork in mod metadata and document disabling it before loading an existing save. The standalone addon patches the same methods and checks for specific IL, so leaving it active can produce a startup error or competing patches. The standalone release remains available for players on upstream AASB2.
